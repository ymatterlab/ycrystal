Your first crystal figure¶

Prerequisites: install Ycrystal, use an X11 desktop with working OpenGL, and install POV-Ray for the PNG step. Commands below start in the checkout root. The built-in sample works without importing a file.

Start and arrange the sample¶

  1. Create an output directory and launch:

    mkdir -p artifacts/first-figure
.venv/bin/ycrystal --sample perovskite

  2. The window shows SrTiO3 and reports 15 atoms and 30 bonds shown, with 1 × 1 × 1 cells. The default view also draws bonds. Eight Sr corner balls and six O face balls are periodic images of the 5 input atoms; the Ti ball is at the centre. Use the Scene ▸ Structure tab to change repetitions; leave them at 1 × 1 × 1 for this tutorial.

  3. Drag with the left mouse button to orbit. Shift + left drag pans; the wheel zooms. Press F over the 3D view to fit everything while keeping the current orientation. View ▸ Reset View restores the initial orientation and fits it.
  4. Click a visible corner ball without dragging. It gets an orange highlight and the status bar reports the element, source atom number, image offset, and fractional/Cartesian coordinates. Press Delete: just that ball disappears and the status shows 14 atoms with 1 hidden (the status also includes bond and cell counts). Press Ctrl+Z to restore it. Press Esc to clear the selection. Hiding changes the figure, not the structure.

Save the project and export the scene¶

  1. Choose File ▸ Save Project (Ctrl+S). Navigate to the checkout's artifacts/first-figure/ directory and save as SrTiO3.ycrystal. The title loses its modified marker (*). The project embeds the structure, view, and display settings, so reopening it does not need a source structure file.
  2. In the Scene dock, open the Render tab and set Width to 640 and Height to 400 (or Width 640 and Aspect 16:10). The toolbar shows 640 × 400 px, and a blue frame in the 3D view marks the image area. Press F to fit the structure into the frame. In the Appearance tab, keep the Satin default material and the White environment (see Materials, backgrounds, and lighting for the other choices).
  3. Choose File ▸ Export POV-Ray… and save as artifacts/first-figure/SrTiO3.pov. Ycrystal writes SrTiO3.pov and SrTiO3.ini in that directory. This step runs no renderer and creates no PNG. Both text files replace existing files of the same name; use a new name to preserve earlier work.

Render the PNG¶

  1. Press F5 for a preview: the POV-Ray preview dock shows a small POV-Ray image of the framed view after a moment. With Update automatically checked, it refreshes shortly after each change.
  2. Choose Render ▸ Check Renderer. Expect a pass message naming POV-Ray and a sphere-centre error below 1 pixel. The check briefly blocks the window. If it fails, follow renderer setup.
  3. Choose Render ▸ Render Image… (Ctrl+R). Keep PNG and Output size (Render panel), set Save as to artifacts/first-figure/SrTiO3.png, and press Render. (The same dialog writes PDF and JPEG files and publication sizes; see rendering.) The status bar shows Rendering … with the progress, and the window stays responsive. Cancel Render would stop it without writing the file.
  4. When complete, a dialog shows the PNG and its path. The image is 640 × 400 pixels. It shows exactly the area inside the blue frame, with the same hidden atoms as the live view and POV-Ray lighting. Orientation axes, the frame, and selection highlights are omitted. See the example render for the default view at 640 × 400.
  5. Press Ctrl+S again to save the output settings. Close the window, relaunch, and use File ▸ Open… to reopen SrTiO3.ycrystal. Coordinates, hidden atoms, output size, and camera are restored, with the same framing in a window of any shape.

Optional: an element legend. Open the Scene ▸ Legend tab and check Show the element legend: ● Sr ● Ti ● O appears at the bottom of the frame. Press Fit View Beside Legend so that the structure sits above it, then render again. See element legend for the layout, font, marker, and order choices.

Your chosen directory now contains the project, two editable scene files, and the PNG. GUI renders use a separate temporary job directory and remove it after completion. They do not render the exported .pov file; editing that file requires running its .ini directly.
