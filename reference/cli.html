Command line, batch rendering, and desktop¶

main ¶

main(argv: list[str] | None = None) -> int

Run the ycrystal command.

Parameters:

  • argv (list[str] | None, default: None ) –

    Command-line arguments without the program name; None uses sys.argv.

Returns:

  • int –

    Exit status: for --check-renderer, 0 if the renderer passed and 1 otherwise; else the status of the Qt event loop when the window closes.

Notes

--check-renderer runs run_self_test with the --povray path (if given), prints PASS: … or FAIL: …, and exits without creating a QApplication. It does not read the executable chosen in the GUI.

--render OUT.png and --export-pov OUT.pov work without a window or display: they draw FILE (a project exactly as saved, or a structure with the default settings and view) through ycrystal.batch, print one line, and return 0, or 1 with an ERROR: message on standard error (2 for invalid sizes). --style STYLE.ycstyle first applies a style to FILE with apply_style_file; --style-parts chooses the parts (default CLI_STYLE_PARTS). What the style could not apply is printed as WARNING: lines on standard error; an unreadable style, or display settings that would show too many atoms, is an error and nothing is written. --width and --height override the style's output size. --element-map Sr=Ba,Ti=Zr sends the style's element settings to other elements (parse_element_map); an invalid or ambiguous mapping is an error before anything is written. --view, --camera-policy, --fit-margin, and --view-height choose the camera (ViewPolicy); without them a project is drawn with its saved camera and a structure with the fitted default view, as before. --style without --render or --export-pov is a usage error (status 2).

--save-project FIGURE.ycrystal (with --render) also saves the figure as a self-contained project with the camera and size it was rendered with, and a provenance record FIGURE.provenance.json, through render_snapshot; the image is rendered from that project, and the three files are written only if the render succeeds. Existing project or provenance files are replaced only with --overwrite; the input, the style, and the image are never replaced (status 1 in both cases, nothing written).

--batch MANIFEST.json --output-dir DIR renders every job of a manifest (ycrystal.manifest) and returns 0 if all succeeded, 1 if any job failed (or POV-Ray is missing), and 2 if the manifest is invalid (then nothing is rendered). --dry-run checks everything and renders nothing. --install-desktop / --uninstall-desktop manage the menu launcher on Linux and the Start-menu entry on Windows (see ycrystal.desktop); on macOS, and in the packaged Windows program (whose installer manages its entry), they print an error and return 1 without writing anything.

Otherwise a window opens with the --sample structure. A FILE argument is opened once the event loop runs; if it cannot be read, a message appears and the sample stays open. Settings are stored for the organization "Y-Matter Lab" and the application "Ycrystal" (~/.config/Y-Matter Lab/Ycrystal.conf on Linux, ~/Library/Preferences/com.y-matter-lab.Ycrystal.plist on macOS).

batch ¶

Render or export projects and structure files without opening a window.

Used by ycrystal --render and ycrystal --export-pov. A project is drawn exactly as saved (camera of the output image, output size, materials, environment); a structure file gets the default display settings and the default view. No VTK code is imported, so these functions work without a display; Qt is used only to draw an element legend (FR-LEGEND-01), without a window.

With --style (FR-STYLE-CLI-01), apply_style_file first applies a .ycstyle file with the transfer rules of apply_style, as File ▸ Import Style… does in the window. The command line applies the parts in CLI_STYLE_PARTS unless told otherwise.

Examples:

>>> import tempfile
>>> from pathlib import Path
>>> from ycrystal.batch import export_scene, load_input
>>> project = load_input("tests/fixtures/SrTiO3.cif")
>>> with tempfile.TemporaryDirectory() as tmp:
...     pov, ini = export_scene(project, Path(tmp) / "SrTiO3.pov", width=320, height=240)
...     ("Width=320" in ini.read_text(), pov.name)
(True, 'SrTiO3.pov')

A style designed for SrTiO3 applied to MgB2: the environment and output size transfer, the Ti and O overrides do not (MgB2 has neither), and a note says so.

>>> from ycrystal.batch import apply_style_file
>>> mgb2 = load_input("tests/fixtures/MgB2.cif")
>>> styled, notes = apply_style_file(mgb2, "examples/grey-studio.ycstyle")
>>> styled.environment.preset, (styled.output.width, styled.output.height)
('studio_grey', (800, 600))
>>> styled.scene.repetitions  # display settings are not applied by default
(1, 1, 1)
>>> print(notes[0])
Element overrides for O, Ti were not applied: the structure has no O, Ti.

CLI_STYLE_PARTS module-attribute ¶

CLI_STYLE_PARTS = ('appearance', 'environment', 'output')

Style parts that ycrystal --style applies when --style-parts is not given.

display (repetitions, cell edges, bonds, atom size, hidden atoms) is left out: the repetitions and hidden atoms of the style's own structure rarely suit another one. Ask for it with --style-parts appearance,display,environment,output. The window's File ▸ Import Style… still offers all four parts.

parse_style_parts ¶

parse_style_parts(text: str) -> tuple[str, ...]

Parse a comma-separated list of style parts, as given to --style-parts.

Spaces around names are ignored, and a repeated name counts once; the result is in the order of STYLE_PARTS.

parse_style_parts("environment, appearance") ('appearance', 'environment')

Raises:

  • ValueError –

    If the list is empty, has an empty entry, or names an unknown part.

parse_element_map ¶

parse_element_map(text: str) -> dict[str, str | None]

Parse an element mapping, as given to --element-map (FR-STYLE-MAP-01).

SOURCE=TARGET pairs separated by commas: the style's settings for SOURCE go to TARGET. SOURCE=- leaves them out. Symbols are case-sensitive; spaces around them are ignored. Whether the targets exist in the structure is checked when the style is applied.

parse_element_map("Sr=Ba, Ti=Zr, O=-")

Raises:

  • ValueError –

    If an entry is empty or has no =, a symbol is not a chemical element, or a source element appears twice.

apply_style_file ¶

apply_style_file(project: Project, style: str | Path | Style, parts: Iterable[str] = CLI_STYLE_PARTS, max_atoms: int = LARGE_DISPLAY_ATOMS, element_map: dict[str, str | None] | None = None, camera_kept: bool = True) -> tuple[Project, tuple[str, ...]]

Return a new project with a style applied, and notes on what was left out.

Parameters:

  • project (Project) –

    Target project (a saved project or a structure read by load_input). It is not modified.

  • style (str | Path | Style) –

    Style file (JSON or a ZIP package with a background picture), or a loaded Style. Loading registers the package's picture and custom material definitions for this session.

  • parts (Iterable[str], default: CLI_STYLE_PARTS ) –

    Parts to apply, a subset of STYLE_PARTS; default CLI_STYLE_PARTS.

  • max_atoms (int, default: LARGE_DISPLAY_ATOMS ) –

    Limit on displayed atoms when the style's display settings raise the count.

  • element_map (dict[str, str | None] | None, default: None ) –

    Optional {source element: target element or None} for styles made for another composition (see resolve_element_map); None transfers by matching symbols.

  • camera_kept (bool, default: True ) –

    Whether the project's saved camera will be used as it is. False (a view policy refits the camera) leaves out the note about new repetitions.

Returns:

  • tuple –

    (project, notes): a new project sharing the structure, with the settings of apply_style, and one sentence per part that was not applied or deserves attention (for warnings, not errors).

Raises:

  • StyleError –

    If the style file cannot be read.

  • StyleTransferError –

    If parts is empty or names an unknown part, if element_map is invalid or ambiguous for this structure, or if the style's display settings would raise the number of displayed atoms above max_atoms.

Notes

The structure, its vectors (components and attachments), and the project's saved camera are kept. A structure without a camera gets the default view fitted to the styled geometry when it is drawn (see scene_for). A style's repetitions are not applied if they would display more than max_atoms atoms and more atoms than the project already shows; a project saved with many atoms is drawn as before.

scene_for ¶

scene_for(project: Project, width: int | None = None, height: int | None = None, view: ViewPolicy | None = None) -> tuple[DisplayGeometry, Camera, RenderSettings]

Return the geometry, camera, and output settings that draw project.

Parameters:

  • project (Project) –

    What to draw.

  • width (int | None, default: None ) –

    Output size in pixels; None keeps the project's size.

  • height (int | None, default: None ) –

    Output size in pixels; None keeps the project's size.

  • view (ViewPolicy | None, default: None ) –

    How to choose the camera (FR-CAMERA-01); None is ViewPolicy(): the saved camera when there is one, otherwise the default view fitted to the output aspect ratio.

Notes

A saved camera that is kept, with a different width or height, keeps its centre and visible height (only the visible width follows the new aspect ratio), as in the window. A fitted camera is fitted at the final aspect ratio, to the framing bounds of the drawn scene: atoms, cell edges, and complete vector arrows. With an element legend at an edge of the image, a fitted camera keeps the scene out of the legend's area (legend_fit_region).

Raises:

  • CameraPolicyError –

    If the view cannot be produced (a lattice axis without a cell, or a scene that does not fit in a fixed visible height).

manifest ¶

Render a series of structures from one JSON manifest (FR-BATCH-01).

ycrystal --batch MANIFEST --output-dir DIR renders every job of a manifest to a PNG, one after the other, without a window. Each job is an ordinary single figure, built with the same functions as ycrystal FILE --style … --render OUT.png (load_input, apply_style_file, ViewPolicy, render_png); a manifest only states them once, for many structures.

The run has two phases:

  1. Validation reads the manifest, every input, and every style, applies the styles and element mappings, chooses each camera, and checks the outputs. Every problem of every job is reported; if there is any, nothing is rendered or written.
  2. Rendering runs the jobs in manifest order. A failed job does not stop the others; every image is written only when its render succeeded. A JSON report records every job.
Manifest format (schema 1)

A UTF-8 JSON object::

{
    "format": "ycrystal-batch",
    "schema_version": 1,
    "defaults": {"style": "grey-studio.ycstyle", "view": "a", "width": 600},
    "jobs": [
        {"id": "SrTiO3", "input": "../tests/fixtures/SrTiO3.cif"},
        {"id": "BaZrO3", "input": "../tests/fixtures/BaZrO3.cif", "element_map": {"Ti": "Zr"}},
    ],
}

jobs is required and lists the figures in order. Each job has an id (letters, digits, ., _, -; unique) and an input (a structure file or .ycrystal project). Any of the following settings may appear in defaults (for every job) or in a job (for that job only, replacing the default):

output PNG file name inside the output directory (default <id>.png); subfolders are allowed, .. and absolute paths are not. format Input format, poscar, cif, qe, or project (default: detected). style .ycstyle file, or null for none. style_parts is a list of parts (default appearance, environment, output, as for --style). element_map {"Ti": "Zr", "O": null}: give the style's settings for an element to another element (null leaves them out); see resolve_element_map. view, camera_policy, fit_margin, view_height The camera, as --view, --camera-policy, --fit-margin, and --view-height. width, height Image size in pixels (16–8000); default: the input's size, or the style's. max_atoms Largest number of displayed atoms allowed (default 20,000); larger scenes are refused at validation, never truncated.

Paths in a manifest are relative to the manifest's folder (absolute input and style paths are allowed). Unknown keys are refused, so a misspelt setting is not ignored.

"save_projects": true at the top level (FR-REPRO-01) saves, next to each rendered image NAME.png, the figure's self-contained snapshot NAME.ycrystal and its provenance record NAME.provenance.json (see ycrystal.provenance); the report then names both for every rendered job. They are checked like images: existing files only with --overwrite, and never an input, style, or the manifest.

provenance ¶

Self-contained figure snapshots and render provenance (FR-REPRO-01).

ycrystal FILE … --render OUT.png --save-project FIGURE.ycrystal, and "save_projects": true in a batch manifest, save two files next to a rendered image:

FIGURE.ycrystal, the snapshot An ordinary project file holding the figure as it was drawn: the structure, the scene settings after the style and element mapping were applied, the environment with its background picture, the definitions of the custom materials it uses, the vectors, the output size, and the camera actually used (saved or fitted). It needs neither the original structure file nor the style, picture, or personal materials, and replaying it neither reapplies a style nor refits the camera::

    ycrystal FIGURE.ycrystal --render replay.png

FIGURE.provenance.json, the provenance record Which inputs, settings, and software made the image; see provenance_record.

The image is rendered from the saved snapshot file, so the snapshot draws the same scene by construction. The three files are moved into place only after POV-Ray has succeeded, the provenance record last: a failed render leaves none of them (and no temporary file) behind, and no record ever describes an image that was not made.

What is reproduced, and what is not

Replaying a snapshot gives exactly the same structure, scene settings, camera, and image size, hence the same POV-Ray scene. Pixels are a different matter: another POV-Ray build, another system, or other standard include files (metals.inc, …, which belong to the POV-Ray installation and are not part of the snapshot) may change the image slightly. The SHA-256 of the image identifies that file; it is a fingerprint, not a proof that someone else reproduced it.

No absolute paths are recorded. Paths in a provenance record are relative to the record's folder; a file outside that folder is identified by name and SHA-256 only. The snapshot also leaves out the absolute path of the original structure file from the structure's import record (its name, format, and SHA-256 remain).

Examples:

>>> from ycrystal.batch import load_input
>>> from ycrystal.core.camera import ViewPolicy
>>> from ycrystal.provenance import provenance_path, snapshot_project
>>> project = load_input("tests/fixtures/MgB2.cif")
>>> project.camera is None
True
>>> snapshot = snapshot_project(project, width=400, view=ViewPolicy(view="c"))
>>> snapshot.camera is not None, (snapshot.output.width, snapshot.output.height)
(True, (400, 800))
>>> source = snapshot.structure.metadata["source"]  # the import record, without the path
>>> "path" in source, source["sha256"] == project.structure.metadata["source"]["sha256"]
(False, True)
>>> provenance_path("figures/MgB2 c.ycrystal").name
'MgB2 c.provenance.json'

desktop ¶

Desktop integration on Linux and Windows: menu entry, icon, and project file type.

ycrystal --install-desktop installs, for the current user only (no sudo, no administrator rights), the entry of the system's applications menu (install_menu_entry); ycrystal --uninstall-desktop removes it. macOS has no such entry yet.

On Linux it writes:

  • $XDG_DATA_HOME/applications/ycrystal.desktop: the launcher shown in the Linux Mint menu (category Science). It starts the ycrystal command of the environment it was installed from, by absolute path, and opens files passed to it;
  • $XDG_DATA_HOME/icons/hicolor/scalable/apps/ycrystal.svg: the icon;
  • $XDG_DATA_HOME/mime/packages/ycrystal.xml: the file type application/x-ycrystal-project for *.ycrystal projects, so that projects open in Ycrystal from the file manager.

$XDG_DATA_HOME defaults to ~/.local/share. The desktop and MIME databases are refreshed when update-desktop-database and update-mime-database exist.

On Windows (install_start_menu):

  • Ycrystal (development).lnk in the user's Start-menu folder of programs: it starts the environment's pythonw.exe (no console window) with -m ycrystal.app and carries the application id of installations from source, so that the running window can be pinned to the taskbar;
  • ycrystal.ico in %LOCALAPPDATA%\Y-Matter Lab\Ycrystal, drawn from the SVG icon;
  • the file type Ycrystal.Project for *.ycrystal projects in HKEY_CURRENT_USER\Software\Classes, so that projects open in Ycrystal from File Explorer.

These belong to the installation from source only. The packaged Ycrystal (the Windows installer, packaging/windows) has its own shortcut Ycrystal, application id, and file type, written and removed by its installer; --install-desktop refuses to run in it (is_packaged). Each side removes only what it wrote, and the source installation never takes the opening of .ycrystal files from another program, so either can be uninstalled without harming the other.

Examples:

>>> from ycrystal.desktop import desktop_entry
>>> entry = desktop_entry("/opt/ycrystal/.venv/bin/ycrystal")
>>> 'Exec="/opt/ycrystal/.venv/bin/ycrystal" %f' in entry
True
>>> "MimeType=application/x-ycrystal-project;" in entry
True

windows_shortcut ¶

Windows shortcuts (.lnk files) that carry an application id, without extra packages.

Ycrystal's Start-menu entry is a shortcut with the application id YMatterLab.Ycrystal (the shell property System.AppUserModel.ID), the id its window sets when it starts. Windows then shows the running window under the shortcut's name and icon, and Pin to taskbar pins the shortcut. WScript.Shell and similar tools cannot set that property, so shortcuts are written and read here through the shell's own COM interfaces (IShellLinkW, IPropertyStore, IPersistFile) with ctypes. Windows only: on other systems the functions raise OSError.
