POV export and render jobs¶

pov_writer ¶

Write a POV-Ray 3.7 scene (.pov) and render settings (.ini) from the shared scene.

The camera is written with explicit location/direction/right/up vectors taken from Camera; look_at and sky are not used, so POV-Ray does not re-derive the basis or flip handedness. Coordinates are the original right-handed world coordinates in ångström, which keeps the scene readable and editable.

Scenes use only POV-Ray 3.7 language features (#version 3.7;). Materials that use native POV-Ray identifiers (for example T_Gold_3C) #include the standard files that declare them; other scenes are self-contained. Colours are written as sRGB values and converted to linear light inside the scene (assumed_gamma 1.0); the .ini file writes the PNG with sRGB gamma. The writer produces text only; running POV-Ray is the job of ycrystal.render.jobs.

FLOOR_TILT_DEG module-attribute ¶

FLOOR_TILT_DEG = 20.0

Tilt of the floor towards the viewer, in degrees (0 would show it edge-on).

scene_to_pov ¶

scene_to_pov(geometry: DisplayGeometry, camera: Camera, environment: Environment, settings: RenderSettings, *, title: str = 'Ycrystal scene', renderer_note: str | None = None) -> str

Return the text of a POV-Ray scene.

Parameters:

  • geometry (DisplayGeometry) –

    Atoms and cell edges to draw; hidden atoms are already absent from it.

  • camera (Camera) –

    View to reproduce.

  • environment (Environment) –

    Background, floor, transparency, and lighting.

  • settings (RenderSettings) –

    Output size and background transparency. The size sets the camera's visible width and height; it should match the size in the .ini file. The background is transparent if either settings.transparent_background or environment.transparent is set.

  • title (str, default: 'Ycrystal scene' ) –

    Text of the first comment line.

  • renderer_note (str | None, default: None ) –

    Optional comment naming the renderer the scene was written for.

Returns:

  • str –

    The scene text. Its header lists the standard #include files the materials need (see required_includes); a scene without them is self-contained.

Raises:

  • PresetError –

    If a material of the geometry is not a known preset.

Notes

The camera is orthographic, with direction set to the unit viewing direction and right and up set to the screen vectors scaled to the visible width and height in Å. Its location lies on the line through the focal point along the viewing direction, far enough back to keep everything drawn (and, with a floor, the whole frame) in front of the eye; under orthographic projection this does not change the image.

Lights come from resolve_lighting: they are placed around the camera's focal point at 4 R + |C - F| + 10 Å (R and C from the geometry's bounding sphere), the key light in the environment's direction (a circular, oriented area light without jitter when light_size > 0, so renders are deterministic) and a shadowless fill light at the lower right; a light with non-positive intensity is omitted. There is no distance attenuation.

A floor is a plane below the drawn spheres as seen in the frame, tilted by FLOOR_TILT_DEG towards the viewer; in an orthographic view it fills the background. Gradients and skies are painted on a backdrop plane behind the scene, aligned with the frame (a sky_sphere would be a single colour in an orthographic view); it sits in a light_group without lights because it needs no lighting. Transparent backgrounds leave out floor and backdrop. The optional reflection panel is a bright disc on the key-light side of the structure (3 R from C) marked no_image: invisible to the camera, it appears only in reflections.

Each material is declared once per element colour (once in total for materials with their own pigment), as a texture or a material. Materials in unit texture space are applied to a unit sphere that is scaled and moved to each atom. Each atom is a sphere with a comment giving its 1-based source atom number, element, and image offset; a comment states how many atoms are hidden. Bonds are two half cylinders with the material of their endpoint atoms, using geometry.bond_radius. Cell edges are cylinders with spheres at the corners, marked no_shadow.

The header records the generation time (UTC), so two exports of the same scene differ in that line.

Lighting¶

lighting ¶

Resolved lighting rig shared by the POV-Ray writer and the live views (FR-LIGHT-01).

The lighting controls of an Environment are relative values: angles in the output camera's screen basis and a size in units of the scene radius. resolve_lighting turns them into world-space positions in Å for a given output camera and displayed geometry. The POV-Ray writer, the live view's light approximation, and the Lighting Setup window all use this one result, so they cannot disagree. Nothing here depends on Qt, VTK, or POV-Ray syntax, and nothing is stored: the rig is derived from the environment, the camera, and the geometry whenever it is needed.

Conventions

The basis is the output camera's (right, up, direction) from Camera.basis; direction points from the eye into the scene, so -direction points toward the viewer.

  • Origin: the camera's focal point F (the point at the image centre).
  • Distance: D = 4 R + |C - F| + 10 Å, with C and R the centre and radius of DisplayGeometry.bounding_sphere (displayed atoms including boundary images and repetitions, plus cell edges; hidden atoms excluded).
  • Key light: F + D (cos(el) (sin(az) right - cos(az) direction) + sin(el) up). Azimuth 0 and elevation 0 point from F toward the viewer; positive azimuth turns toward screen right, positive elevation toward screen up. Orbiting or rolling the camera turns the whole rig with the image.
  • Fill light: fixed direction normalize(0.70 right - 0.25 up - 1.0 direction) (lower right, toward the viewer: azimuth +35.0°, elevation -11.6°) at the same distance, always shadowless.
  • Intensities are white light in linear units; there is no distance attenuation.
  • Light size: the key light becomes a circular area light whose diameter is light_size × R Å, sampled on a 5 × 5 grid with adaptive refinement and no jitter; orient turns the disc toward each shaded point, so it acts like a sphere of that diameter rather than a fixed panel.
  • Reflection panel: a disc of radius 1.6 R at C + 3 R × key direction, facing back along the key direction (anchored on C, not F).

Examples:

>>> from ycrystal.core.camera import Camera
>>> from ycrystal.core.lighting import resolve_lighting_for_bounds
>>> from ycrystal.core.scene import Environment
>>> camera = Camera((0, 0, 30), (0, 0, 0), (0, 1, 0), parallel_scale=5.0)
>>> env = Environment(key_azimuth=-65, key_elevation=25, key_light=1.3, fill_light=0.12)
>>> rig = resolve_lighting_for_bounds(env, camera, center=(0, 0, 0), radius=4.0)
>>> rig.distance
26.0
>>> [round(float(v), 3) for v in rig.key.position]
[-21.356, 10.988, 9.959]
>>> rig.key.is_area, rig.fill.shadows
(False, False)

Output size¶

aspect ¶

Output-size arithmetic with an optional locked aspect ratio (FR-RENDER-01).

The Render panel keeps a target ratio r = width / height. While the ratio is locked, editing one dimension computes the other from r in whole pixels; r itself is kept across edits and never recomputed from the rounded dimensions, so repeated edits do not drift. These functions hold that arithmetic without Qt, so the panel, the window, and the tests share one implementation.

Examples:

>>> from ycrystal.core.aspect import linked_size, swapped
>>> ratio = 2400 / 1600
>>> linked_size("height", 1920, (2400, 1600), ratio, locked=True)
(2880, 1920)
>>> linked_size("width", 3000, (2400, 1600), ratio, locked=True)
(3000, 2000)
>>> linked_size("height", 1920, (2400, 1600), ratio, locked=False)
(2400, 1920)
>>> swapped((2400, 1600), ratio)
((1600, 2400), 0.6666666666666666)

The POV-Ray preview has its own size (FR-PREVIEW-01): a chosen width, and the height that keeps the output's shape.

>>> from ycrystal.core.aspect import preview_size

[(480, 320), (800, 533), (1200, 800)]
>>> preview_size((1600, 2400), 480)[:2]

Image export (PNG, PDF, JPEG)¶

export ¶

Image export: formats, figure sizes, and resolution arithmetic (FR-EXPORT-01).

POV-Ray renders a raster image; Ycrystal writes it as PNG, PDF, or JPEG. This module holds the arithmetic shared by the export dialog, the window, and the tests, without Qt. Writing the files is ycrystal.render.formats.

Four quantities are kept apart:

  • the pixel size POV-Ray renders (width × height), which is the size of the PNG and JPEG and of the image embedded in the PDF;
  • the resolution in dots per inch, stored as metadata in PNG and JPEG files and used to compute the PDF page size;
  • the physical size, pixels / dpi × 25.4 mm;
  • the size the user entered, in pixels or millimetres (figure_pixels converts it).

>>> from ycrystal.core.export import pixels_from_mm, mm_from_pixels

>>> pixels_from_mm(180, 600)  # double column at 600 dpi
4252
>>> round(mm_from_pixels(2008, 600), 2)
85.01
>>> figure_pixels("mm", 85, 85 / 1.5, 600)
(2008, 1339)
>>> [round(mm, 2) for mm in ExportOptions("pdf", 2008, 1339, dpi=600).physical_size_mm()]
[85.01, 56.68]

formats ¶

Write a rendered POV-Ray image as PNG, PDF, or JPEG (FR-EXPORT-01).

POV-Ray always writes an 8-bit PNG at the requested pixel size (with an element legend, Ycrystal has already painted it onto that PNG, see ycrystal.render.legend). This module turns that image into the file the user asked for, without resampling it:

  • PNG: the rendered file byte for byte; with a resolution, a pHYs chunk is inserted after the header (the image data are not decoded or re-encoded).
  • JPEG: decoded once and encoded once with the chosen quality. JPEG has no alpha channel, so a transparent background is composited over white first. The JFIF header carries the resolution.
  • PDF: one page whose size is the physical size of the image at the chosen resolution, with the image embedded losslessly (Flate) at its full pixel size and any alpha channel kept as a soft mask. The PDF contains a raster image: it is not a vector drawing and does not become sharper when enlarged. PDF page sizes are whole PostScript points (1/72 inch), so the page may differ from the exact physical size by up to half a point (0.18 mm); the image is centred on it without distortion.

Every format is written to <destination>.part, checked, and then renamed over the destination, so a failed export never leaves a truncated file under the final name. Uses Qt's image classes (QImage, QPdfWriter), which need no window or display.

jobs ¶

Render jobs: isolated temporary directories with short ASCII file names.

POV-Ray runs with the job directory as its working directory and writes only there. This avoids problems with spaces/non-ASCII characters in user paths and works within POV-Ray's I/O restrictions (povray.conf normally permits the working directory). The finished image is copied to the user's destination by Python afterwards.

A job goes through these steps; the caller owns the job directory throughout:

  1. prepare_job creates a new directory ycrystal-job-* (in the system temporary directory by default) containing scene.pov and scene.ini.
  2. POV-Ray runs with that directory as its working directory, either synchronously with run_job or asynchronously with RenderProcess. It writes scene.png.
  3. finish_job turns the exit status and log into a RenderResult; renderer failures are reported in the result, not raised. If the job has an enabled element legend, it is painted onto the image now (ycrystal.render.legend), so that every use of the image (preview, export, command line) has it.
  4. copy_result copies the image to its destination.
  5. RenderJob.cleanup deletes the directory. Nothing in this module does that automatically.

Element legend¶

legend ¶

Paint the element legend onto images (FR-LEGEND-01).

The legend is drawn in two dimensions with Qt's QPainter and is independent of the three-dimensional scene: POV-Ray renders the structure exactly as without a legend, and draw_legend_on_file then paints the legend onto the rendered PNG at its full pixel size (in finish_job). PNG, PDF, and JPEG exports, the preview, and the command line all start from that image. The live view draws the same legend with legend_overlay, so what the frame shows is what the image gets.

To stay sharp and identical at every size, the layout is computed once at a reference text size and scaled to the image: the text height is a fixed fraction of the image height (see LegendSettings). Symbols are drawn as the outlines of their glyphs, antialiased, without font hinting or subpixel (coloured) antialiasing, so they look the same in a 480-pixel preview and a 6000-pixel export, and the edges carry no colour fringes in print.

Painting text needs a QGuiApplication. In the window there is one; the command line creates one without windows when the first legend is drawn (ensure_gui_application).
