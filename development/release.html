Release procedure and checklist¶

How a Ycrystal release is prepared, and the checklists of versions 0.3.0, 0.2.0, and 0.1.0. Publication (tag, GitHub release, making the repository public) is the maintainer's decision and is not part of this procedure.

Procedure¶

  1. Update __version__ in src/ycrystal/__init__.py and CHANGELOG.md.

  2. Run the checks on the reference machine (Linux Mint, X11, POV-Ray 3.7 package):

    .venv/bin/pre-commit run --all-files
YCRYSTAL_REQUIRE_INTEGRATION=1 .venv/bin/python -m pytest -q -rs
.venv/bin/python scripts/docs_examples.py
.venv-docs/bin/zensical build --clean --strict

    tests/test_release.py includes the end-to-end workflow (open a CIF, rotate and pan, expand to 2 × 2 × 2, change an element's finish, choose a studio, render, save, close, reopen without the source file, render again, then POSCAR and QE imports (ibrav = 0 and ibrav = 1) and the rejection of a QE file whose lattice pw.x would refuse), the command line, the desktop launcher, and the examples. 3. Clean install: in a new directory, follow Install and launch exactly (clone, venv, pip install -e . -c constraints.txt), then run ycrystal --version, --check-renderer, an example --render, a short GUI launch, and --install-desktop into a temporary XDG_DATA_HOME checked with desktop-file-validate. 4. Build the artifacts and install the wheel into another fresh environment:

    uv build -o dist        # dist/ycrystal-X.Y.Z.tar.gz and -py3-none-any.whl
/usr/bin/python3 -m venv /tmp/yc-wheel
/tmp/yc-wheel/bin/python -m pip install dist/ycrystal-X.Y.Z-py3-none-any.whl -c constraints.txt
/tmp/yc-wheel/bin/ycrystal examples/SrTiO3-studio.ycrystal --render /tmp/check.png

    The wheel contains the presets, thumbnails, and icon; the source distribution adds constraints.txt, the examples, the test fixtures, and the notices. 5. The Windows installer (on a Windows computer, or the ycrystal-windows-installer artifact of the Windows installer workflow run of the release commit): build it with packaging\windows\build.ps1, run packaging\windows\coexistence-check.ps1, install it once by hand (wizard, Start menu, a preview), and attach Ycrystal-X.Y.Z-windows-x64-setup.exe to the GitHub release. It is not signed; see Windows installer. 6. Record the results in docs/PROGRESS.md and in the checklist below, marking each item passed, failed, or unverified.

Requested by the user on 18 November 2026: tag v0.4.0 once PR #40 (the Windows installer) passed CI, update the files that record the version, then audit the README before deciding on a GitHub release. The version was set by its own pull request (branch release/v0.5.0); the tag marks its merge. Steps 2–4 of the procedure (the reference-machine run, a clean install by a person, the wheel) were not run for this tag; each feature was verified when merged (see docs/PROGRESS.md).

Checklist for 0.3.0¶

Version 0.3.0 did not follow the procedure above. The maintainer tagged v0.3.0 on 16 November 2026 at the merge of the macOS work (commit 6ed6b03) after CI passed there, before __version__ and the changelog were updated; both were updated afterwards on main. The features in 0.3.0 were each verified when they were merged (see docs/PROGRESS.md); the release checklist itself was not run.
