Windows port¶

Windows support was developed on branch feature/windows (PR #35): the groundwork on the Linux laptop and Windows CI (17 November 2026), the completion on a Windows 11 laptop (18 November 2026). This page records:

  • what was decided, and what is known with sources;
  • what is implemented and how it was tested;
  • the answers found on the Windows computer;
  • what is still open.

Status (18 November 2026): Ycrystal runs from a source checkout on Windows 11 with POV-Ray for Windows 3.7. On one laptop it passes every automated test (below), and the user tested it by hand there and reports that it works well. Since PR #36, Windows CI renders with the real POV-Ray for Windows too (see CI). Since PR #39, one script installs it, with a Start-menu entry (see installation); that is now the developer installation. For users, a graphical installer (PyInstaller + Inno Setup) installs it without Python, Git, or PowerShell, side by side with the developer installation (see Windows installer).

Decision¶

Taken by the user on 17 November 2026: Ycrystal runs natively on Windows, and renders with the official POV-Ray for Windows 3.7 (pvengine64.exe).

The alternatives were set aside: - WSL2 only: Ycrystal and Linux POV-Ray inside WSL2. - Hybrid: native Ycrystal with wsl povray for rendering.

They remain possible later and are not implemented.

What is implemented on feature/windows¶

Linux and macOS behaviour is unchanged: povray gets exactly the arguments it got before and still runs as a QProcess; every existing test passes on Linux.

  • src/ycrystal/render/povray.py (the place for renderer platform checks):
  • is_windows_engine() recognises pvengine*.exe by name.
  • windows_engine_candidates() and installed_windows_engine(platform) find POV-Ray for Windows from the registry Home values and the ProgramFiles folders (it is not on PATH); find_povray() falls back to it after povray on PATH.
  • render_arguments(): ["scene.ini"] for povray; ["/EXIT", "/NR", "+GAscene.log", "scene.ini"] for POV-Ray for Windows, which prints nothing and writes all messages to scene.log (read_log()).
  • background_startupinfo() starts it minimised (SW_SHOWMINNOACTIVE).
  • hold_foreground() / release_foreground() / foreground_held(): POV-Ray for Windows makes itself the foreground window even when started minimised or hidden. While it runs, Ycrystal calls LockSetForegroundWindow, which Windows allows only to the owner of the foreground window, so it works in the window and is refused harmlessly in a terminal. Holds are counted; every hold asks for the lock again.
  • windows_engine_conflict(): the same test POV-Ray makes at start-up (a window of its main class exists, and OneInstance is not 0 in its pvengine.ini), so that Ycrystal reports ENGINE_OPEN_MESSAGE instead of starting a copy that would show POV-Ray's modal error box and wait. keeps_single_instance() reads the setting as GetPrivateProfileInt does.
  • include_directories() also reads the user-files folder recorded in the registry (DocPath; right also when Documents was moved, for example into OneDrive), then Documents\POV-Ray\v3.7 in the home folder.
  • povray_version() never starts POV-Ray for Windows (no --version; it would open its window); it reads the executable's version resource.
  • src/ycrystal/render/jobs.py: run_job() reports a conflict without starting POV-Ray, holds the foreground while it runs, starts it minimised, and appends its log.
  • src/ycrystal/render/process.py (the window's previews, final renders, and material thumbnails): PySide6 6.12 has no QProcess.setCreateProcessArgumentsModifier, so QProcess cannot start a program minimised. POV-Ray for Windows therefore runs as a subprocess.Popen, checked every 100 ms by a QTimer. Since only one copy can render, the program's own runs take turns (a render started while another runs waits, and counts as running); whether one runs is decided by the process itself, and a waiting render checks for its turn on its own timer, so a render whose Qt object was deleted cannot hold up the others. Cancelling kills POV-Ray and reports at once. It reports no progress (POV-Ray for Windows prints none): the window shows a busy indicator, then 100 %.
  • src/ycrystal/gui/native.py: set_taskbar_identity() (an explicit AppUserModelID, so that the window has its own taskbar button and icon, not Python's; called from app.py before the application object) and executable_filter() (Render ▸ Set POV-Ray Executable… lists .exe files on Windows). That dialog now starts at the POV-Ray Ycrystal would use, not at povray on PATH.
  • Tests:
  • tests/conftest.py: python_program() makes stand-in programs work everywhere (a .cmd launcher on Windows); the povray_executable fixture also finds an installed POV-Ray for Windows.
  • tests/test_windows_povray.py checks the Windows contract on any system with stand-ins: arguments, log, version query, folder search and the recorded user folder, the Popen backend (success, failure, cancel, failure to start, preview superseding, renders taking turns, a deleted render not holding up the next), the foreground holds, the single-instance setting, and the conflict check. One test runs only on Windows, against the installed program.
  • Tests that simulate "no POV-Ray" by emptying PATH also hide an installed POV-Ray for Windows. A test that renders an exported scene by hand uses render_arguments() (with povray unchanged: povray scene.ini).
  • tests/test_preview_resolution.py compares scene files with the header's time aside (a minute could pass between two states: a flake on every system, seen first on Windows, where each preview takes longer).
  • .gitattributes: text files keep LF line endings in Windows checkouts. Several tests compare SHA-256 digests of tracked files.
  • scripts/make_examples.py writes LF on every system.
  • scripts/windows_povray_probe.py reports how POV-Ray for Windows behaves under Ycrystal; it also prints the settings file and the single-instance setting and stops when another copy is open.
  • CI (.github/workflows/ci.yml): a third test job on Windows Server 2022 with Python 3.12; experimental in PR #35, required and rendering with POV-Ray for Windows since PR #36 (see CI).
  • Documentation: a Windows section in the install guide and the README, rows in the support matrix and troubleshooting, the architecture page, and the changelog.

Answers to the questions of the takeover¶

2 Exit status after success and after a parse error? 0 in both cases. After a parse error there is no image, and finish_job() already treats "status 0, no image" as a failure, explained from the log
3 Does scene.log hold POV-Ray's messages, including "Parse Error"? Yes (options, warnings, statistics, and the parse error with file and line). No progress lines
4 Does a dialog appear on the first start? Yes, two of them (found on the CI runner, see CI): the editor question on every start until the editor is installed or turned off, and the About box from the second start on, again every 14 days. On the laptop, the very first render produced no image within 90 s and the next start took 28 s: by then the user had installed the editor (its DLLs appeared in the installation folder during the session) and the About box had been shown and closed (ItsAboutTime set). POV-Ray's settings also hold [DontShowAgain] OneInstanceSet=1, the one-time Keep Single Instance notice. The completion-sound and output-file notices never appear with /EXIT (source)
5 Does the window stay minimised and not take the focus? Minimised: yes (watched in every state, "Starting" to "Done"). Focus: no — it makes itself the foreground window even when started minimised or hidden (SW_HIDE). Implemented for the window; a terminal cannot do it, so --render loses the terminal's focus while POV-Ray runs. SW_HIDE would also keep its taskbar button away; minimised was kept, so that a POV-Ray dialog stays reachable

POV-Ray for Windows on CI¶

povray.org answers GitHub's runners with a browser challenge, so CI cannot download the installer from there. Of the options considered on 17 November 2026 (a: keep the official installer as a release asset of this repository; b: a self-hosted runner; c: POV-Ray 3.8 beta; d: no POV-Ray on Windows CI), the user chose a on 18 November 2026 (PR #36):

  • The official installer, unmodified (SHA-256 above), is the asset povwin-3.7-agpl3-setup.exe of the release ci-assets (not a Ycrystal release; its notes give the licence, AGPL-3.0, and the source, github.com/POV-Ray/povray). The Windows job downloads it with its own token, refuses another checksum, and installs it silently.
  • Before POV-Ray's first start the job writes UseEditors=0 and ItsAboutTime (the latest 32-bit time) into the runner's pvengine.ini; without them, the editor question and the About box waited for an answer (screenshots of scripts/windows_povray_probe.py --screenshots, uploaded by the job).
  • The job is no longer experimental: it runs the renderer check, the documentation examples, and the tests without windows with YCRYSTAL_REQUIRE_INTEGRATION=1. First passing run: 727 passed, 2 skipped (POSIX-only tests), GUI tests not run (as on macOS: run them on a Windows computer).
  • Before the repository or the release becomes public, check the AGPL-3.0 obligations for passing the installer on (the release notes point to the source).

Installation in one command¶

Asked by the user on 18 November 2026 ("is there a simpler method for installation?"). The manual installation had eight steps: - install Git and Python, then open a new terminal (else py is not found); - clone; create .venv; run the long pip line; - download POV-Ray for Windows from povray.org and install it; - start POV-Ray once to settle its editor question; - start Ycrystal from PowerShell every time (no Start-menu entry).

Its traps were the stale PATH and the editor question: a render then waited silently at a dialog in a minimised window.

Implemented:

  • scripts/install-windows.ps1 (ASCII, for Windows PowerShell 5.1, which every Windows 11 has): Python 3.12 with winget --scope user unless py finds Python 3.12, 3.13, or 3.14 (in this order; older ones are refused, also in an existing .venv) (it re-reads PATH from the registry, so no new terminal is needed); .venv; pip install -e . -c constraints.txt; POV-Ray for Windows with winget unless found; if POV-Ray would ask about its editor, it opens once with instructions; the Start-menu entry; --check-renderer. Idempotent; exit status 0 only when everything is ready, with a list of what is not otherwise. Options -Python, -Dev, -NoPovray, -NoStartMenu.
  • --install-desktop on Windows (desktop.py, windows_shortcut.py):
  • Ycrystal.lnk in the user's Start-menu folder (SHGetKnownFolderPath). It starts .venv\Scripts\pythonw.exe -I -m ycrystal.app, so that no console window opens; -I keeps a ycrystal module in the starting folder from shadowing the package, and is used only inside a virtual environment.
  • The shortcut carries the application id YMatterLab.Ycrystal, the one set_taskbar_identity() gives the window. It is written through IShellLinkW, IPropertyStore, and IPersistFile with ctypes, since WScript.Shell cannot set it.
  • An .ico with 8 sizes drawn from the SVG by Qt, in %LOCALAPPDATA%\Y-Matter Lab\Ycrystal.
  • The file type Ycrystal.Project for .ycrystal under HKEY_CURRENT_USER\Software\Classes. The user's own Open with choice (UserChoice) is left alone, and so is an .ycrystal key that points elsewhere at uninstall.
  • --uninstall-desktop removes all three; macOS still refuses both options.
  • The editor question is reported instead of waited for: windows_engine_conflict() returns EDITOR_QUESTION_MESSAGE when editor_question_pending() holds, so --check-renderer, previews, and renders fail at once with the remedy. Stand-in programs (.cmd) are never checked.
  • Windows CI runs the script in Windows PowerShell 5.1 into a new .venv (with -Python from setup-python, POV-Ray already installed) and reads the shortcut back.

Still open¶

  1. Hands-on use. The user tested Ycrystal by hand on the Windows laptop on 18 November 2026 and reports that it works well; which items were tried was not recorded. On another Windows computer, a fuller check can follow the macOS checklist in HANDOFF.md, adapted: the window draws sharply at the display's scale; mouse and touchpad; selection; menus and Ctrl shortcuts; File Explorer dialogs; Set POV-Ray Executable… and Check Renderer; previews with Update automatically (the POV-Ray taskbar button, the keyboard focus staying in Ycrystal); a long render cancelled; closing the window during a render; a project saved on Linux or macOS renders the same on Windows and back; whether POV-Ray plays a sound (none expected with /EXIT).
  2. POV-Ray for Windows' About box for users. Every 14 days (and at the second start after installation) POV-Ray for Windows shows its About box when it starts, also when Ycrystal starts it minimised, and waits for OK; the render waits with it. This is documented (install guide, troubleshooting). Ycrystal does not change the user's POV-Ray settings; whether it should detect the box and bring it forward is undecided.
  3. The installation script on a new computer (see installation): with neither Python nor POV-Ray installed, so that the winget steps and the editor prompt run; then Pin to taskbar on the running window.
  4. Out of scope until decided:
  5. code signing of the graphical installer, which exists since branch feature/windows-installer (PyInstaller + Inno Setup; see Windows installer) but is not signed;
  6. Windows on ARM; Windows 10;
  7. progress percentages during renders with POV-Ray for Windows. It prints none, but its window title carries them (POV-Ray for Windows [Rendering scene.pov: 37%]), which a later change could read;
  8. an option to start POV-Ray hidden (SW_HIDE) instead of minimised.
