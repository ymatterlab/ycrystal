Python examples¶

These are evolving developer interfaces. Run from a source checkout with the application dependencies installed; see the generated reference for detailed parameter contracts. The documentation build itself executes none of these examples.

Without a display or renderer¶

This is a short interactive example from the scene reference:

>>> from ycrystal.core.samples import perovskite_srtio3
>>> from ycrystal.core.scene import SceneSettings, build_geometry
>>> structure = perovskite_srtio3()
>>> geometry = build_geometry(structure)
>>> len(structure), len(geometry)
(5, 15)
>>> corner = (0, (1, 1, 1))
>>> hidden = build_geometry(structure, SceneSettings(hidden=frozenset({corner})))
>>> len(hidden), hidden.hidden_count, hidden.index_of(corner)
(14, 1, None)

Display repetitions and periodic bonds are available through the same model:

>>> expanded = build_geometry(structure, SceneSettings(repetitions=(2, 2, 2)))
>>> len(expanded), len(expanded.bonds)
(71, 192)

Scientific coordinates are unchanged. The arrays produced by build_geometry are read-only, and the image offset is relative to input positions rather than wrapped positions. See scene and geometry.

Materials and environments are chosen by preset id. Scene settings carry the default material and per-element or per-atom overrides; the geometry resolves one material per displayed atom, and the environment carries background, floor, and lighting:

>>> from ycrystal.presets import environment_from_preset
>>> styled = SceneSettings(material="glass").with_element_material("Ti", "gold")
>>> geometry = build_geometry(structure, styled)
>>> sorted(set(geometry.materials))
['glass', 'gold']
>>> studio = environment_from_preset("studio_white")
>>> studio.floor, studio.lighting
(True, 'studio')

See material, environment, and lighting presets and the appearance guide.

Execute the complete lightweight example with:

.venv/bin/python scripts/docs_examples.py

The script also projects the focal point, imports tests/fixtures/MgB2.cif, saves/reopens a project, and exports .pov/.ini text in a temporary directory, including a glass scene on a transparent background and a white-studio scene with element and atom material overrides, and applies that scene's style to MgB2. It checks the expected outcomes and cleans its files. It does not import the viewport or run POV-Ray. Source docstrings contain further runnable examples; see the doctest command.

With POV-Ray, without a display¶

.venv/bin/ycrystal --check-renderer --povray /usr/bin/povray
.venv/bin/python scripts/docs_render_example.py --output artifacts/docs/perovskite.png

The second command demonstrates the synchronous job lifecycle: prepare_job → run_job → inspect RenderResult.ok/message → copy_result → job.cleanup() in finally. The result's image_path is inside the temporary job directory and becomes invalid on cleanup. Keep the copied destination instead. Discovery and filesystem setup can raise; ordinary renderer failures return a result. See rendering reference.

With a display and OpenGL¶

.venv/bin/ycrystal --sample perovskite

Follow the first-figure tutorial. Creating MainWindow or StructureViewport needs QApplication, a display, and OpenGL. Asynchronous RenderProcess needs a running Qt event loop but no window; it leaves job cleanup to the caller. Its finished signal delivers one RenderResult for success or failure. The GUI copies a successful result and then cleans the job.
