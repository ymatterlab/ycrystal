Known limitations and unresolved issues:

  • Background pictures show only their average colour in the live VTK view; there is no rename/delete UI for personal materials; live-view speed with thousands of vector arrows is unmeasured; the Lighting Setup overview does not draw vector arrows.
  • macOS: Ycrystal runs from the source checkout. There is no application bundle, so the Dock and the menu bar show "Python", and .ycrystal files do not open by double click.
  • macOS: nothing has been checked by hand yet, and no Retina display was available (see Cross-platform status).
  • Windows: Ycrystal runs from the source checkout, installed by scripts\install-windows.ps1 and started from the Start menu (or .venv\Scripts\ycrystal.exe). POV-Ray for Windows renders one copy at a time (Ycrystal reports a copy the user has open), reports no progress percentage, and takes the keyboard focus during renders started from a terminal. POV-Ray for Windows shows its About box at its second start and then every 14 days; renders wait until the user clicks OK (documented; Ycrystal changes no POV-Ray setting). Its question about a missing editor at every start is now reported by Ycrystal instead of waited for. Rendering with a %TEMP% path outside a legacy code page (for example a Chinese user name on a Western-European Windows) is unverified.
  • FR-EXPORT-01: the PDF holds the POV-Ray raster image (not vector graphics); PDF page sizes are whole points (up to 0.18 mm from the exact size); JPEG fills a transparent background with white. Not yet run on Linux or checked by hand.
  • FR-REPRO-01: pixel differences of snapshot replays between systems or POV-Ray builds are unmeasured (same machine: identical pixels, never identical PNG bytes); not run on macOS; snapshots only for PNG renders from the command line.
  • FR-VALIDATION-01: everything was measured on the Linux laptop only. Not run: the benchmark and the validation tests on the Mac, the full benchmark set (too heavy for the laptop), and replays between two machines (commands in docs/development/validation.md). The comparison with VESTA, OVITO, and CView is from their documentation only. No independent evaluation has taken place.
  • FR-GALLERY-01: the gallery was rendered on the Linux laptop only. Its snapshots have not been replayed on another machine. Figure 1 (schematic, screenshot) and the plots of Figure 4 are still to be made (docs/development/manuscript-figures.md).
  • JAC submission: referees need anonymous access to the program and a web page with documentation (per the journal's instructions; recheck them). The repository is now public, so the program can be cloned without an account; the documentation web page is still to be decided.
  • Found during FR-REPRO-01, not changed: save_project (and so every project and snapshot) is written through mkstemp and ends up readable by the owner only (mode 0600 on Linux/macOS), which matters for shared folders. The new provenance records behave the same. Decide whether to change it (a separate task).

Hands-on checks on a Mac¶

Automated tests cannot establish these. Start with .venv/bin/ycrystal --sample perovskite and note what fails.

  • [ ] The window opens, the structure is drawn sharply, and it fills the whole view (on a Retina display: not a quarter of it, not blurred).
  • [ ] Mouse: left drag orbits, Shift + left drag pans, right drag and the wheel zoom. Trackpad: two-finger scrolling zooms at a usable speed; pinching zooms.
  • [ ] Click selects the atom under the cursor (also on a Retina display); ⌘ + click toggles; Delete (⌫) hides; Esc clears.
  • [ ] Menus: Ycrystal's Quit is in the application menu; ⌘O, ⌘S, ⇧⌘S, ⌘Z, ⇧⌘Z, ⌘R, ⌘M, ⌘← / ⌘→, F (Fit), and F5 (Preview; may need Fn) work with the 3D view focused.
  • [ ] File dialogs: Open lists POSCAR/CONTCAR files without an extension, .cif, .pw.in; Save Project adds .ycrystal; Render Image… (PNG, PDF, JPEG) and Export POV-Ray… save.
  • [ ] Render ▸ Set POV-Ray Executable… starts in the folder of the found executable; Render ▸ Check Renderer passes.
  • [ ] Preview with Update automatically on: one preview per change, no repeated re-rendering while idle, also in a small window.
  • [ ] Supercell handles, measurement modes, Lighting Setup window (drag the key light), Vectors window, Customize Material… (saving a personal material creates its thumbnail), background picture.
  • [ ] Appearance: readable in macOS dark mode; colour dialog and galleries.
  • [ ] A long render can be cancelled; closing the window during a render exits cleanly.
  • [ ] A project saved on Linux opens on the Mac and renders the same image, and the reverse.

Development environment notes¶

Common to all systems: one virtual environment per machine and per checkout (.venv; .venv-docs for the documentation). A virtual environment copied from another operating system does not work: recreate it with python3.12 -m venv --clear .venv.

Linux Mint 22 / Ubuntu 24.04:

sudo apt install git povray povray-includes libxcb-cursor0 python3.12-venv
/usr/bin/python3 -m venv .venv          # the system Python, not Conda

macOS (Homebrew; verified on macOS 15.8, Apple silicon):

xcode-select --install                  # Git and command-line tools, if missing
brew install python@3.12 povray         # POV-Ray 3.7 with its include files
python3.12 -m venv .venv

Then, on either system, from the repository root:

.venv/bin/python -m pip install -e ".[dev]" -c constraints.txt
.venv/bin/ycrystal --version            # ycrystal 0.4.0
.venv/bin/ycrystal --check-renderer     # PASS: POV-Ray 3.7… passed
.venv/bin/ycrystal --sample perovskite  # opens the window
.venv/bin/python -m pytest -q -rs       # GUI tests open windows for about 1.5 minutes
.venv/bin/pre-commit run --all-files
python3.12 -m venv .venv-docs && .venv-docs/bin/python -m pip install -r docs/requirements.txt
.venv-docs/bin/zensical build --clean --strict

POV-Ray is found in this order: the path saved with Render ▸ Set POV-Ray Executable…, the environment variable YCRYSTAL_POVRAY, then povray on PATH (command -v povray shows it: /usr/bin/povray from apt, /opt/homebrew/bin/povray from Homebrew on Apple silicon). The include files are looked up in the installation of that executable.

Troubleshooting:

  • Linux: "Could not initialize GLX" or an xcb plugin error: use /usr/bin/python3 outside Conda and install libxcb-cursor0. Without a desktop session run the tests with xvfb-run -a.
  • macOS: python3.12: command not found — install python@3.12 with Homebrew; the system python3 is too old. Conda's Python is unverified.
  • macOS: Qt prints "Can not manage visual effect areas in views without a container layer" for the 3D view; it had no visible effect in the tests.
  • macOS: GUI tests take the keyboard focus while they run; leave the machine alone or run pytest -m "not gui".

Windows 11 (set up 18 November 2026 on a laptop with a 125 % display scale; PowerShell from the repository root). The installation script installs Python 3.12 and POV-Ray for Windows with winget where missing, .venv with the developer tools (-Dev), the Start-menu entry, and checks the renderer:

powershell -ExecutionPolicy Bypass -File scripts\install-windows.ps1 -Dev
# By hand instead: winget install --id Python.Python.3.12 --exact --scope user;
# winget install --id PersistenceOfVisionRaytracer.POVRay --exact; a new terminal;
# py -3.12 -m venv .venv; .venv\Scripts\python.exe -m pip install -e ".[dev]" -c constraints.txt
.venv\Scripts\ycrystal.exe --check-renderer
$env:YCRYSTAL_REQUIRE_INTEGRATION = "1"
.venv\Scripts\python.exe -m pytest -q -rs      # GUI tests open windows for several minutes
.venv\Scripts\pre-commit.exe run --all-files
py -3.12 -m venv .venv-docs; .venv-docs\Scripts\python.exe -m pip install -r docs/requirements.txt
.venv-docs\Scripts\zensical.exe build --clean --strict
  • Windows: the python on PATH of a fresh Windows is a Microsoft Store alias that opens the Store (and hangs a script); use py -3.12 or the venv's python.exe. "The term 'py' is not recognized" means the terminal was opened before Python was installed (VS Code's terminal until VS Code restarts): open a new one.
  • Windows: a clone made from main before .gitattributes existed has CRLF text files (Git for Windows sets core.autocrlf=true), and switching to a branch with .gitattributes does not rewrite them; tests that hash tracked files then fail. Use a fresh clone of a branch that has .gitattributes. (On 18 November 2026 the files of this checkout were converted to LF only where the result hashed to the blob in the index, then git add -u refreshed Git's file information; nothing was staged.)
  • Windows: POV-Ray for Windows must not be open while tests or Ycrystal render (it keeps a single instance; Ycrystal reports it). Run nothing else that renders in parallel with the test suite.

Decisions and deferred features¶

  • FR-VECTOR-02 (CSV/TSV vector tables) is deferred. Its specification is kept in the private plan for possible future use; do not implement or scaffold it unless the user explicitly asks to reactivate it. No feature request has been rejected so far.
  • One repository and one codebase for all systems; no platform branches. Platform checks stay in gui/native.py, desktop.py, render/povray.py, and tests/conftest.py.
  • A resize of the view is not a change of the figure (16 November 2026).
  • macOS CI runs without GUI tests; the GUI is verified on a real Mac.
  • Python: 3.12, 3.13, and 3.14 are supported; requires-python >=3.12 (18 November 2026). CI runs 3.12 on every system and 3.13 and 3.14 on Ubuntu only, within the user's limit of twice the 3.12-only CI cost; check this when adding jobs. Windows with 3.13 and 3.14 was verified by hand on the laptop (full suite, 18 November 2026), not in CI.
  • Vectors: Cartesian components in the structure frame; magnetic moments in μB, directions dimensionless; source defaults plus image overrides/suppressions; no inferred signs or magnetic symmetry; styles carry arrow appearance, never vectors.
  • Pictures and custom materials are content-addressed (SHA-256 / content-derived ids); projects embed the custom definitions they use, so they open on a clean profile.
  • Projects/styles are ZIP packages only when they carry a picture; otherwise JSON.
  • Personal materials are stored in QSettings (materials/personal) with thumbnails in a material-thumbnails/ folder (per machine, not in Git; locations above).
  • Preview resolution presets are widths (Small 480, Medium 800, Large 1200, Custom).
  • Gallery (FR-GALLERY-01):
  • The low-symmetry case uses kyanite, COD 1008755 (real, ordered, P-1, CC0, authors credited), not the invented triclinic fixture.
  • The SrTiO3 variants are rendered from the paper figure's snapshot with the cover style, so geometry, camera, and size are identical by construction.
  • Full-size renders stay out of Git. The docs carry only 480 px JPEG thumbnails of real renders, regenerated by the gallery script.
  • The independent-user sheet is the existing checklist, extended; no second sheet.
  • Validation (FR-VALIDATION-01):
  • Images are checked by measured properties, never against stored pixels.
  • Tolerances: sphere centre 0.5 px, disc area 8 %, fitted bounds 1.5 px, scene file 5e-7 Å; each is justified in docs/development/validation.md.
  • Views for image checks are chosen analytically on a 10° grid.
  • The benchmark uses the production command in new processes (median and range; peak memory through a launcher process, see PROGRESS.md).
  • The comparison with other programs rests on their documentation only, quoted with links.
  • Evaluator answers are written only by the evaluators.
  • Snapshots (FR-REPRO-01): the snapshot is an ordinary .ycrystal project (no new recipe format, no project schema change) holding the resolved scene, camera, and output size; the image is rendered from the saved snapshot; image, snapshot, and record are moved into place only after a successful render, the record last. Snapshots drop the absolute path from the structure's import record; provenance paths are relative to the record's folder, files outside it get path: null (name and SHA-256 only). Existing snapshot/record files need --overwrite; the input, style, image, or manifest are never replaced; --render still replaces its PNG. Manifest key save_projects is top-level (schema 1 kept; older Ycrystal refuses the unknown key); report schema 1 gains project/provenance per job. The image SHA-256 is a fingerprint only: POV-Ray writes the render time into every PNG.
  • Batch (FR-BATCH-01): validate the whole manifest first, report every problem, render nothing if any (status 2); sequential jobs; no overwriting without --overwrite; a failed job does not stop the others (status 1); PNG only; paths relative to the manifest; unknown keys refused; max_atoms default 20,000.
  • Views (FR-CAMERA-01): one rule for the window and --view (core/camera.py::axis_view); a, b, c are real-space vectors; a saved camera is kept unless a view, a fixed height, or --camera-policy fit is asked for; fitted views include whole arrows; a fixed visible height that does not fit is an error, never a crop. No reverse views on the command line (--view -a would clash with option parsing).
  • Element mapping (FR-STYLE-MAP-01): explicit only, never inferred; unmapped elements match by symbol; ambiguity (shared targets, a mapped element landing on one with its own settings) is an error, never resolved by order; per-atom settings never follow a mapping; the mapping is not stored in the style. CLI syntax SOURCE=TARGET, - to leave out. The dialog hook is now MainWindow.ask_style_import (was ask_style_parts).
  • Styles from the command line (FR-STYLE-CLI-01): default parts appearance,environment,output (ycrystal.batch.CLI_STYLE_PARTS), display on request; the GUI's Import Style dialog is unchanged. A saved project keeps its camera. A style may not raise the display above 20,000 atoms (LARGE_DISPLAY_ATOMS) from the command line; there is no override. Notes are WARNING: lines on stderr.
  • QE ibrav (FR-QE-IBRAV-01, 21 November 2026): pw.x's lattice vectors exactly (INPUT_PW, latgen.f90), all 20 lattices, pw.x's parameter checks; ibrav = -13 with the axes of QE 6.5 and later (5.2.0–6.4.1 used others); a CELL_PARAMETERS card with ibrav ≠ 0 is refused as pw.x does; crystal_sg stays unsupported. QE's GPL test files are not copied into the repository; scripts/check_qe_ibrav.py downloads them.
  • Element legend (FR-LEGEND-01, 21 November 2026): a 2D layer, never part of the 3D scene or the .pov export; painted onto the rendered PNG at full size after POV-Ray (all image paths), and as an overlay in the live view, by one layout. Sizes are relative: text height in % of the image height, the rest in text heights. Entries come from DisplayGeometry (drawn colours; majority colour per element). Stored in SceneSettings.legend (project schema 8, style schema 3, appearance part). Fitting (window and fitted command-line views) leaves the legend's area free; saved cameras are never moved. Default font: Arial, Helvetica, Liberation Sans, Nimbus Sans, or DejaVu Sans, the first installed. Disabled by default; then images are unchanged.
  • Export (FR-EXPORT-01): one POV-Ray render per export at the export pixel size; pixels and dpi are the source of truth (mm derived); no resampling; JPEG transparency → white; PDF = raster image on a page of the physical size, never called vector; the export does not change the project's output size; dialog settings last for the session only (not QSettings).

Handoff and maintenance rules¶

  • This file is a record of the project's state, not an authorization to implement anything. The order of authority is in CLAUDE.md ("Priority of instructions").
  • At the start of a session read CLAUDE.md, this file, and the requirements that concern the task; then check git status and the recent git log to see the actual state. If a document disagrees with the code or the history, investigate; do not assume the document is right.
  • After a substantial task, update "Latest development session", the status table, and the next steps, from results you observed. Do not report unrun tests as passed or planned work as done.
  • Keep entries short and actionable. Move finished detail to PROGRESS.md instead of growing this file, and keep unresolved issues until they are resolved.
  • No machine-specific absolute paths, personal details, or credentials in this file.
